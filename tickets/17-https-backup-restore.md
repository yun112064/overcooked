## 交付成果

交付雲端常駐 HTTPS 網站、依賴團隊電腦的 YOLO／營養知識 RAG 接入及可恢復備份流程。

## 2026-11-12 使用者決議：與 demo 分支相同的部署方式

- 不租雲端主機、不申請網域：整套系統在團隊電腦的 Docker（`compose.prod.yaml`，專案 meal-prod），對外只經 Cloudflare 快速通道（trycloudflare.com，網址每次重開都會變），費用為 0。`scripts/prod-up.ps1` 啟動、`prod-down.ps1` 關閉。
- 飲食小幫手接入且回答改回地端：Ollama 的 `embeddinggemma`（同日決議移除 `bge-m3`）、`qwen3.5:9b`，重排 `bge-reranker-v2-m3` 用 TEI 容器（Ollama 沒有重排介面）。語料與索引由 `scripts/assistant-data.ps1` 建立。快速通道官方不支援 SSE；實測 POST 串流可即時送達。
- AC24 不列入驗收：團隊電腦關機、睡眠或斷網時整站離線。下方第 1、2 條中「兩端」「一般雲端功能及歷史仍可用」改以單機理解；本機服務未啟動時仍須顯示不可用並保留輸入。
- 備份：`scripts/backup-daily.ps1` 每日備份業務庫、知識庫、小幫手庫並複製到獨立位置（`install-prod-tasks.ps1` 註冊工作排程器）；重排權重不備份，依 `REVISION` 重新下載。

## 驗收條件

- 以 Compose 提供雲端網站，對外 HTTPS 由 Cloudflare named tunnel＋自有網域處理，Caddy 只在內部提供 HTTP、不處理憑證（2026-11-11 使用者決議）；團隊電腦提供 YOLO、知識 RAG 與飲食小幫手檢索（回答由雲端模型生成）；兩端連線有身份驗證及加密，資料庫不直接公開。記錄 RAG 資料／索引所在節點及啟動方式。
- 團隊電腦在線可執行辨識／RAG，關機或斷線顯示服務不可用並保留輸入；一般雲端功能及歷史仍可用，恢復後可重試。知識 RAG 離線不能當成正常查無知識；雲端食譜查詢不依賴該服務。
- 依 Spec 路徑及秘密設定部署；Schema 使用 Alembic，部署前備份，不可安全降版時採還原而非盲目破壞性降版。
- 每日將兩端必要資料及來源／規則快照備份到獨立位置，起始保留七日；至少一次實際還原後驗證家庭與餐食可讀、RAG 所需資料可恢復或重建，交付操作證據及限制。
- 記錄所選服務實際報價與費用占用，遵守總額上限；不得將部署完成宣稱為五人容量已通過。

## 2026-10-12 節點及恢復

- 雲端 PostgreSQL 保存結構化食譜庫與家庭歷史；團隊電腦保存營養知識庫／pgvector 索引及提供 YOLO，食譜查詢不再位於本機。
- 備份／還原包含兩端知識來源及引用快照、雲端已採用歷史與菜色識別；索引可重建，保留來源版本。離線測試須區分雲端查無菜單、自動 AI 回退、本機知識查無與本機故障。
