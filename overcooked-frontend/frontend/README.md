此目錄預設執行正式 API 版本，沿用原本示範版的焦橘、奶油白、淡紫、廚師帽與蔬果主視覺。原示範版仍保留，可獨立切換。介面程式、套件與測試集中在 `overcooked-frontend/`；主專案啟動入口也已統一指向此版本。

已提供隔離的 Docker API、資料庫與背景工作示範，帳號及啟動方式見 [展示環境說明](../demo/README.md)。此環境使用合成營養數值，畫面會持續標示展示狀態。

## 啟動正式版

請先讓主專案既有後端依原流程運作；本目錄不會啟動資料庫、worker、模型服務或執行遷移。

```sh
cd /Users/kuyun/Documents/AIPE04_team_5/overcooked/overcooked-frontend/frontend
npm ci
npm run dev
```

開啟 **http://localhost:5173/**。主專案的 `start-dev.cmd`／`scripts/start-dev.ps1`、一般 Compose 與正式 Compose 現在皆使用此目錄。若已有前端正在執行，請先停止後重新啟動。`--strictPort` 會在端口被占用時停止，避免自動換端口後與後端的 Origin 驗證設定不符。

- 瀏覽器呼叫 `/api`，Vite 去掉此前綴後轉到 `http://127.0.0.1:8000`。
- 若既有後端位於其他位址，可透過原本支援的 `VITE_API_PROXY_TARGET` 環境變數指定；本次沒有更改後端端口或設定。
- 使用 `localhost` 開啟頁面，沿用後端已允許的前端來源；不要自行換端口或改用 `127.0.0.1` 網址。
- 登入／註冊會呼叫真實 API，Cookie 隨請求送出。正式版沒有「示範登入」或本機帳號資料回退。
- 此資料夾上一層的 `compose.yaml` 與 `backend/` 是早期後端骨架，沒有主專案的完整 API；請勿用它們替代現行後端。

- 結果：整理成食譜／採購／營養／分餐四個頁籤。頁籤切換不卸載內容，不因此重送營養或知識生成請求。

## 結果與辨識版型補齊（2026-11-15）

- 食譜預覽、正式生成與共用歷史元件採用左側菜色選單、右側配方詳情；桌面食材與步驟分欄，窄螢幕堆疊顯示。菜色切換不重新計算或呼叫生成服務。
- 正式結果使用後端提供的料理照片，缺少照片或載入失敗時顯示「尚無料理照片」。預覽契約沒有照片欄位時同樣顯示缺圖狀態，不套用示範食譜照片冒充真實菜色。
- 辨識流程為先選照片、檢視大型預覽，再按「開始辨識」上傳；保留多種蔬菜逐一修正／確認／略過、重試、刪除及手動搜尋。右側食材清單可移除項目，沿用問卷原本的儲存流程。
- API 與主機端口不變。修改前端入口後，已運行的開發程序須停止重啟；Docker 前端須重新建置才會載入新版本。


## GitHub CI

根目錄 `.github/workflows/t06-ci.yml` 的 **Redesigned frontend** 工作使用 Node.js 24，在此目錄依序執行 `npm ci`、`npm test`、`npm run lint`、`npm run build` 與 `npm run build:demo`。PR 與 main 的推送都會執行；任何一步失敗即回報該工作失敗。

既有 `frontend-build` 保留檢查舊前端，其他後端、辨識服務、管理網站與模擬超市的工作也保留。查看 CI 時請確認最新提交的 **Redesigned frontend** 結果；此工作不會連接真實資料庫、模型、部署網站或發布示範版。
