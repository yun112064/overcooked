# T04 MVP 本機驗收報告

驗收日期：2026-10-16（Asia/Taipei）。驗收對象為本分支 `nutrition_model/` 的 T04 營養估算模組。

**判定：本次更新的 T04 MVP 通過本機驗收，可供隊友接入。原版發現的4類問題已修正，使用者已在本機安裝並重跑53項測試與完整範例通過。** 本報告不代表主系統整合、正式部署或營養估算準確度已通過驗收。

## 驗收依據與方式

依專案的 `nutrition_model/README.md`、`docs/T04-tfda-llm-changes.md` 與原實作計畫核對：TFDA 熟食優先；缺少時使用 TFDA 生食與經驗證的 LLM 參數；USDA 提供產率參考；實際熟重優先；未知營養保留 null；油、鹽、醬料獨立計算；由 Python 計算總量、每份及每 100g。

驗收在隔離工作目錄執行，不讀取原專案的 `.env`，不帶入真實金鑰。本次新增 Gemini 請求為 **0**。設定檔測試僅使用假的測試金鑰。獨立審查涵蓋計算語意、傳輸與命令列邊界、來源工作簿匯入一致性。

## 原版發現與修正

| 問題 | 原版行為 | 修正版行為 |
|---|---|---|
| 已熟食材重量基準 | 熟芝麻加上料理方式後，能繞過重量基準檢查，接受「生重」並算出不一致結果 | 兩個熟食入口都要求已熟食材明確使用熟重 |
| 整道成品實測重 | 營養完整且提供整道熟重後，仍因個別食材熟重未知而標示整道未完成 | 可用整道實測重完成食譜層級計算；不捏造個別食材熟重，也不填補缺少營養 |
| 過大數字輸入 | `10**400` 造成數值驗證例外與程式中斷 | 結構化拒絕無法表示的數字 |
| 未宣告的執行依賴 | 標準 Python 無法啟動 CLI，因為缺少 python-dotenv | CLI 以標準函式庫讀取單行 `.env`，無須額外套件 |

另同步更正 `.env` 自動載入與覆寫順序、重試次數及錯誤訊息遮蔽的文件。修正前，6 個新增回歸測試中出現 4 個失敗、1 個例外；修正後 6 個全部通過。原始營養資料沒有改動。

## 使用限制與未驗項目

1. 只有 878/2,213 筆 TFDA 紀錄有完整七項營養；643 個歧義別名仍安全地拒絕自動配對。這些是資料覆蓋限制。
2. 雞胸肉纖維在原始資料就是 null。缺少熟重或適用產率時保留 null；不能填 0 或假造實測值讓畫面變完整。
3. 預設與備援模型有免費級別，程式不會啟用帳務或自動升級；本次未查詢 Google 專案的實際帳務資格或剩餘額度。
4. 主系統／隊友功能整合、正式部署、代表性真實料理及營養準確度比對，**未納入此次本機驗收，也尚未通過驗收**。
