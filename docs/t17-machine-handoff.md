## 使用者可執行的本機操作與判定

各項在使用者電腦上目前均為 **待執行**，需另附實際證據才可標記通過。符合資源／作業系統條件即可由使用者執行；條件不符時只記錄受影響的項目。執行前先確認拿到含修正的版本，並閱讀 [還原操作與舊備份限制](t17-backup-recovery.md)。

| 驗收項目 | 操作與通過條件 | 證據 |
| --- | --- | --- |
| 啟動與重啟 | 自己的電腦符合 Windows／Docker／GPU 條件時可測 `scripts/prod-up.ps1`；容器、schema gate 與前端健康檢查正常；重跑與重啟不誤用開發庫。沒有 GPU 時先執行不需 TEI 的分項測試 | 提交 SHA、去除秘密的腳本輸出與容器狀態 |
| YOLO／Ollama／TEI | YOLO 權重已在 Git，可用 CPU 測真實推論；Ollama／重排模型可公開下載，依記憶體與相容 GPU 條件啟用。測正常、離線及恢復；效能須註明硬體 | 測試步驟、服務狀態、實際硬體與使用量 |
| 外網與串流 | 網路允許時可自行建立快速通道，從另一個網路測註冊／登入／家庭與 POST 串流，不需沿用同學的網址 | 去除私人內容的操作紀錄、時間戳、HTTP 狀態 |
| 每日備份與副本 | 用合成資料或初始資料包建立自己的三庫測備份與 checksum；有獨立磁碟時可測獨立副本。同磁碟暫存目錄只驗證複製邏輯 | 三份備份時間、位置與核驗結果 |
| 自己測試環境的還原演練 | 還原至新的演練庫與空目錄，核對版本／筆數／測試照片／索引；以受限 app 帳號測登入、家庭與餐食讀寫 | 還原報告、app 帳號操作結果；不得以 postgres 成功代替 app 驗證 |
| Windows 工作排程 | 自己使用 Windows 時可測自身帳號／測試磁碟的排程、結果碼與錯過後補跑；正式主機帳號與磁碟另由同學驗收 | 工作排程狀態與去除秘密的備份日誌 |

演練期間保留原庫與正式連線，使用臨時設定連到演練庫，不直接切換正式 DATABASE_URL。若需檔案與資料庫完全一致，停止相關測試寫入後再備份。演練庫清理由執行者確認名稱後執行。
